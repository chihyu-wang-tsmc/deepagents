01套件地圖

這個 repo 是 monorepo。核心 SDK 約 3.2 萬行，最大的套件反而是終端機代理 dcode（約 22.9 萬行）。所有執行宿主都只透過 create_deep_agent() 使用核心。

  • 核心程式在 libs/deepagents/deepagents/：graph.py、middleware/、backends/、profiles/。
  • 四個沙盒夥伴套件都繼承 BaseSandbox，並跑同一套 SandboxIntegrationTests。
  • JavaScript／TypeScript 版本在另一個 repo（deepagentsjs），不在這裡。

02三層架構

deepagents 沒有自己的執行引擎。它把預設行為組裝好交給 LangChain 的 create_agent()，最後由 LangGraph 執行、存檔、串流、暫停與恢復。

  • 工具或提示詞不對：看 middleware 組裝與 profile。
  • 暫停、恢復、checkpoint、串流的行為：看 LangGraph。
  • 模型怎麼被建立（字串 → 物件）：看 init_chat_model 與 ProviderProfile。

03建構流程：create_deep_agent()

呼叫 create_deep_agent() 時依序做七件事，最後回傳一個 CompiledStateGraph。上方的卡片是每一步用到的參數。

  • 入口在 graph.py:296；:684 決定預設的 StateBackend()；:686 組系統提示；:860 自動加入 general-purpose 子代理；:920 起組主代理堆疊；:1027 呼叫 create_agent(...)。
  • 沒有對應 HarnessProfile 的模型，deepagents 不加任何基底提示（舊的 BASE_AGENT_PROMPT 在 0.7.0 已棄用），工具本身的說明就是指示。
  • .with_config() 把 recursion_limit 設成 9999，並加上 ls_integration="deepagents" 等 metadata，追蹤工具裡看得到。
  • model=None 自 0.5.3 起棄用，1.0 會移除。

04Middleware 堆疊

主代理預設最多 14 層（含插入點之後的條件層）。鉤子的執行順序由 LangChain 決定：before_* 依堆疊順序、after_* 反序、wrap_* 第一層在最外面。

  • 自訂 middleware：名稱和預設層相同就原位取代，否則插在核心層之後、profile 層之前（_apply_custom_middleware）。
  • FilesystemMiddleware 與 SubAgentMiddleware 是必要層，HarnessProfile 不能排除（_REQUIRED_MIDDLEWARE）。
  • general-purpose 子代理自己的堆疊是 Filesystem → Summarization → PatchToolCalls → profile → Skills* → 快取 → ModelRefusal。它只繼承「取代預設同名層」的自訂 middleware，你新加的 middleware 不會進去，所以 Jev 改用 HarnessProfile 掛載。
  • 宣告式子代理的堆疊同上，再接上 spec 裡的 middleware；mode="fork" 時另加 Memory。
  • 預設沒有 TodoListMiddleware（write_todos），只有 OpenAI Codex 與 NVIDIA Nemotron 的設定檔會加上。

05一次執行：LangGraph 節點

LangChain 把每個鉤子變成一個 LangGraph 節點。before_agent 只跑一次，接著在 before_model → model → after_model → tools 之間循環，直到模型給出沒有工具呼叫的回答。

  • 節點名稱是「middleware 名稱.鉤子」，例如 PatchToolCallsMiddleware.before_agent，在 Langfuse 或 LangSmith 的追蹤裡就是這些名字。
  • tools 跑完會回到第一個 before_model 節點（loop_entry_node），不會重跑 before_agent。
  • middleware 可以回傳 jump_to 跳到 model、tools 或 end。例如選用的 RubricMiddleware 在 after_agent 判定要修改時，會把意見送回 model。
  • interrupt() 需要 checkpointer；恢復時用 Command(resume=...) 重跑暫停的那個節點。
  • 迴圈接線在 LangChain 的 langchain/agents/factory.py（約 1614–1900 行）。

06模型呼叫的包覆層

wrap_model_call 像洋蔥，第一層在最外面。請求由外往內被改寫，最裡面才是真正的 LLM 呼叫，回應再一層層傳回去。

  • execute 工具就是在這裡被拿掉的：後端不支援執行時，Filesystem 層把它從這次請求移除。
  • 摘要不改 state：Summarization 層只改寫這次送出的訊息。
  • 快取層與 Memory 放在 profile middleware 之後，是為了避免 memory 內容變動讓 Anthropic 的提示快取前綴失效（graph.py 的註解）。
  • 虛線框是有設定才會出現的層。

07子代理：task 工具

task 工具把工作交給子代理。子代理拿到隔離的 state 和自己的 middleware 堆疊，只把最後一段文字帶回主代理，所以主代理的上下文不會被中間過程塞滿。

類型怎麼定義特點
SubAgent（宣告式）dict：name、description、system_prompt、tools、model、middleware、skills、permissions、interrupt_on、response_format、mode由 create_deep_agent() 幫它組堆疊。mode="fork" 時繼承父代理的訊息，系統提示也完全相同，可以共用提示快取。
CompiledSubAgentname、description、runnable任何 runnable 都可以；回傳的 state 一定要有 messages。
AsyncSubAgentname、description、graph_id、url在遠端 Agent Protocol 伺服器背景執行，見下一節。
  • 回傳內容依序判斷：有 structured_response 就回 JSON；模型拒答就回拒答說明；否則回最後一則有文字的 AIMessage。
  • 子代理和主代理共用同一個 backend。用 StateBackend 時，子代理寫的檔案會經由回傳的 Command 合併回主代理的 files。
  • 排除的 state 鍵在 middleware/subagents.py:447；task 工具本體在 :736 的 _build_task_tool。

08非同步子代理

AsyncSubAgent 不會卡住主代理。它用 LangGraph SDK 在遠端伺服器開 thread 與 run，主代理拿到 task_id 就繼續工作。

  • 五個工具：start_async_task、check_async_task、update_async_task、cancel_async_task、list_async_tasks。
  • 輪詢狀態與完成喚醒只走非同步路徑（Agent Server 用的那條）；同步 invoke 時這些鉤子直接略過。
  • update_strategy：interrupt 取消目前的 run 改跑新的，enqueue 排在後面。
  • 完成通知是在父 thread 用 multitask_strategy="reject" 建一個 run；也可以另外設定 webhook。

09後端 backends

所有檔案工具都透過 BackendProtocol 存取資料。換後端就是換資料放在哪裡，工具與 middleware 都不用改。

  • 預設的 StateBackend 把檔案放在 state 的 files 欄位，跟著 checkpoint 存，只在同一個 thread 有效。
  • execute 只在 backend 實作 SandboxBackendProtocol 時出現；CompositeBackend 的 execute 一律交給 default。
  • LocalShellBackend 用 subprocess.Popen(shell=True) 在主機執行（local_shell.py:256、:659），virtual_mode 限制不了 shell，也就是公司掃描標出的那一段。
  • permissions= 的檢查發生在 FilesystemMiddleware，不在後端。

10上下文管理

長時間執行的代理最怕上下文爆掉。deepagents 用四種方式處理：卸載大結果、卸載大訊息、截斷舊的大參數、摘要。被移出的原文都寫成檔案，模型需要時再用 read_file 讀回來。

  • 門檻由 compute_summarization_defaults()（summarization.py:294）依模型 profile 的 max_input_tokens 決定，沒有 profile 時用固定數字。
  • 不會被卸載的工具：ls、glob、grep、read_file、edit_file、write_file、delete。它們本身有分頁或結果很小。
  • 字數換算用 1 token ≈ 4 個字元（NUM_CHARS_PER_TOKEN）。
  • dcode 另外提供 compact_conversation 工具與 /compact 指令（SummarizationToolMiddleware），讓人或模型手動壓縮。

11Skills 與 Memory

兩者都從 backend 讀檔，策略卻相反：Skills 先只給名稱與描述，需要時才讀全文；Memory 每次執行都完整放進 system prompt。

  • 技能名稱只能用小寫英數與連字號，最多 64 字元，而且要和資料夾同名；description 最多 1024 字元，超過會被截斷。
  • 子代理不繼承父代理的 skills_metadata，會從自己的 sources 重新載入。
  • Memory 的提示會提醒模型：<agent_memory> 是檔案內容，可能過時，不是系統指令。

12人工核准與權限

HITL 讓人在工具執行前做決定：核准、修改參數、拒絕，或直接回答。它靠 LangGraph 的 interrupt()，所以一定要有 checkpointer。

  • 設定方式：interrupt_on={"execute": True}，或用 InterruptOnConfig 限定可用的決定種類。
  • 子代理可以有自己的 interrupt_on；沒設就沿用主代理的。
  • 你的 Jev tool_gate 送出的也是同一種 HITL 格式的 interrupt。

13狀態與持久化

資料放在三個地方：state（跟著 checkpoint，限同一個 thread）、store（跨 thread）、外部檔案系統。

  • DeltaChannel 讓 checkpoint 只存差異，長對話的存檔成長從 O(N²) 降到 O(N)。
  • 私有欄位清單由 private_state_field_names() 收集，交給 SubAgentMiddleware 在進出子代理時過濾。

14設定檔 profiles

同一套 harness 要配不同模型，靠兩種設定檔：ProviderProfile 管模型怎麼建立，HarnessProfile 管代理怎麼組。

  • 只有字串形式的模型會套用 ProviderProfile；直接傳入 BaseChatModel 物件時跳過這一步。
  • HarnessProfile 對主代理、general-purpose 子代理，以及模型相同的宣告式子代理都生效。
  • 內建設定檔在 profiles/harness/；註冊函式是 register_harness_profile（harness_profiles.py:980）與 register_provider_profile（provider_profiles.py:195）。

15Deep Agents Code（dcode）

dcode 是用 SDK 做成的終端機程式代理。它分成兩個程序：客戶端負責畫面、hook 與核准，本機的 langgraph dev 子程序負責建圖與執行。

  • 進入點 main.py；伺服器端的圖在 server_graph.py；agent.py:2535 的 create_cli_agent() 在 :3756 呼叫 create_deep_agent()。
  • Hooks v2：hook 設定與指令留在客戶端，觸發時機（PreToolUse、PostToolUse、Stop 等）由伺服器的 ServerHooksMiddleware 決定，兩邊用 interrupt 往返。
  • 專案的 hooks 會執行指令，所以 headless 與 CI 要加 --trust-project-hooks 才會載入。
  • app.py 一個檔案就有約 3.3 萬行。

16其他執行宿主：ACP、Talon、Evals

這三個套件都是 SDK 的使用者，各自把 deep agent 接到不同的入口。

  • ACP 讓 Zed 這類編輯器透過 stdio 和代理對話；dcode 也能用 dcode --acp 直接當 ACP 伺服器。
  • Talon 是實驗性的 alpha 版，README 明說不適合正式或企業環境。
  • Evals 的結果公開在 LangSmith，CI 由 evals.yml 執行。

17選用擴充

這些不在預設堆疊裡，要自己用 middleware= 或設定檔加上。

SummarizationToolMiddlewaredeepagents提供 compact_conversation 工具，讓模型或人手動壓縮對話；dcode 的 /compact 用它。
